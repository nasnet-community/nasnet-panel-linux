- Install as a server panel, or as a router with multi-WAN failover, VPN pools, Wi-Fi, LAN devices, port forwarding and live traffic diagnostics.
- Router and IP-only installs serve the panel over HTTPS on a certificate it makes itself. Browsers warn once per device; compare the fingerprint shown after install. Subscription links stay on plain HTTP so VPN apps can fetch them.
- Add remote nodes: a VPS runs the node agent and is reached over mTLS, directly or through a reverse connection. One-command installs work without a domain, agents update one by one or in bulk, and every node runs Xray 26.10.10.
- Link nodes with VLESS Reverse tunnels, and run SSH and MTProto tunnels on any node, assigned to subscriptions and cut off with them. MTProto nodes run telemt on a VPS the panel drives.
- Speed limits shape each tier as one pipe per node across all its interfaces and tunnels, and new users or speed changes reach Xray without restarting it.
- Manage users with groups, CSV export, a user page with a timeline, and bans. Subscription pages show what's left and when it runs out, and count WireGuard devices.
- Settings are one page of cards that says what is in effect.
- Track server uptime and outages, take scheduled backups (encrypted when a passphrase is set), and manage certificates.

Upgrading from the first 1.0.0 build (2026-10-13): the updater sees the same version, so run `echo v1.0.0-first | sudo tee /usr/local/nasnet-panel/.version` and then `nasnet auto-update` (Docker installs pull the image again). Then update each node's agent from the Nodes page; speed limits need it. Existing installs keep plain HTTP until you pick Self-signed in Settings → HTTPS.
